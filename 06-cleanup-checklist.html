6. 리소스 정리 체크리스트 및 과금 방지 검증

인프라 실습 종료 후 예상치 못한 클라우드 비용 청구를 100% 방지하기 위해, 리소스 간 의존성을 고려한 올바른 역순 해제(Reverse Teardown)를 수행하고 잔여 자원 0건을 검증했습니다.

⚠️ 클라우드 3대 과금 위험 요인 및 방지 원리

1. 유휴(Idle) Elastic IP 과금

인스턴스가 꺼지거나 종료된 후 방치된 탄력적 IP는 시간당 $0.005의 미사용 패널티 비용이 발생합니다. 종료 즉시 Release 해야 합니다.

2. 영구 보존 EBS 볼륨 과금

인스턴스를 단순 '중지(Stopped)' 상태로 두면 연결된 EBS 볼륨(GB-month)은 계속 과금됩니다. '종료(Terminate)' 시 볼륨을 동시 삭제해야 합니다.

3. 의존성 충돌 (DependencyViolation)

VPC나 보안 그룹을 먼저 지우려 하면 하위 리소스가 종속되어 삭제가 거부되므로, 반드시 하위 계층부터 차례대로 역순 정리해야 합니다.

🔄 의존성 역순 정리 파이프라인 (Reverse Teardown Sequence)

1. EC2 인스턴스 종료
➔
2. Elastic IP 릴리스
➔
3. 보안 그룹 삭제
➔
4. 서브넷 삭제
➔
5. IGW 분리 및 삭제
➔
6. VPC 완전 삭제
