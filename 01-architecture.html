1. 아키텍처 다이어그램 (Architecture Diagram)

AWS 서울 리전(ap-northeast-2) 내 격리된 VPC 네트워크 환경을 설계하고, 외부 사용자 트래픽과 관리자 트래픽의 유입 경로, 라우팅 테이블, 보안 그룹 방화벽 및 EC2 인스턴스 배치를 시각적으로 검증합니다.

📐 인터랙티브 아키텍처 벡터 다이어그램 (SVG)

mission-deployer ✔ EC2/VPC/SG 전용 권한 허용 ✖ AdministratorAccess 금지 ✖ S3, RDS, DynamoDB 미부여 최소권한(Least Privilege) 준수 🛡️ Security Group: mission-web-sg (Stateful) [ Inbound Rules ] Port 80 (HTTP) | TCP | Source: 0.0.0.0/0 (전체 오픈) Port 22 (SSH) | TCP | Source: 내 공인 IP/32 (단독 제한) 🖥️ EC2 Instance: mission-web-server 인스턴스 유형: t2.micro / t3.micro (Free Tier) OS: Ubuntu 22.04 LTS | 스토리지: 8GiB gp3 EBS 웹 서버: Nginx 1.x (Port 80) / Docker Container 고정 외부 IP: Elastic IP (54.180.1.48) 연결 완료 Traffic Routing (IGW → SG → EC2)

🧱 7단계 아키텍처 상세 컴포넌트 분석

1 격리 VPC 네트워크

CIDR 10.0.0.0/16 (총 65,536개 사설 IP 대역)을 할당하여 다른 AWS 고객 및 공용 인터넷과 논리적으로 완전 격리된 가상 사설망을 구축했습니다.

식별자: mission-vpc 리전: ap-northeast-2
2 퍼블릭 서브넷 분리

서울 리전 1번 가용영역(ap-northeast-2a)에 10.0.1.0/24(가용 IP 251개) 서브넷을 생성하고 자동 공인 IP 할당을 활성화했습니다.

식별자: mission-public-subnet AZ: ap-northeast-2a
3 인터넷 게이트웨이 (IGW)

VPC의 양방향 인터넷 통신 창구인 mission-igw를 생성하여 VPC에 Attach하고, 외부 세계와의 패킷 라우팅을 매개합니다.

식별자: mission-igw 상태: Attached
4 라우팅 테이블 (Route Table)

내부 사설망 트래픽(10.0.0.0/16)은 local로 통신하며, 외부 인터넷(0.0.0.0/0) 대상 트래픽은 mission-igw를 타깃으로 등록했습니다.

식별자: mission-rtb 연결: Public Subnet
5 보안 그룹 (Stateful SG)

가상 상태 저장 방화벽을 적용하여 HTTP 80번 포트는 전 세계(0.0.0.0/0)에 오픈하고, SSH 22번은 관리자 단일 IP(/32)로 제한하여 0-65535 포트 침투를 차단했습니다.

그룹명: mission-web-sg 정책: Default Deny
6 컴퓨트 & 고정 EIP

프리티어 규격인 t2.micro(1 vCPU, 1GiB RAM) 인스턴스에 Ubuntu 22.04 LTS 및 8GiB gp3 EBS를 장착하고, 고정 IP(54.180.1.48)를 바인딩했습니다.

인스턴스: mission-web-server 공인 IP: 54.180.1.48

🚀 패킷 흐름 라이프사이클 (End-to-End Traffic Path)

STEP 1
클라이언트 요청 시작: 사용자가 브라우저에서 http://54.180.1.48:80을 호출하여 SYN 패킷을 인터넷으로 송신합니다.
STEP 2
인터넷 게이트웨이 수신: AWS 백본망을 거쳐 mission-igw에 도착한 패킷은 VPC 내부 대상 서브넷으로 전달됩니다.
STEP 3
보안 그룹 인바운드 검사: mission-web-sg가 TCP 포트 80에 대해 허용 규칙(0.0.0.0/0)을 확인하고 인스턴스로 패킷 진입을 인가합니다.
STEP 4
Nginx 웹 서버 처리: EC2 커널이 패킷을 수신하여 Nginx 프로세스(Port 80)로 전달하고 HTTP 200 OK HTML 페이로드를 생성합니다.
STEP 5
아웃바운드 자동 반환 (Stateful): 보안 그룹의 상태 저장(Stateful) 특성으로 인해 응답 패킷은 별도 아웃바운드 규칙 없이도 클라이언트에게 즉시 회신됩니다.
