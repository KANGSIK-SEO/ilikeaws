# 🛠️ 트러블슈팅 보고서 (Troubleshooting Report)
## 주제: 클라우드 인스턴스 삭제 후 300만 원 폭탄 과금 사태와 대시보드 부재 환경에서의 계정 전면 삭제 트러블슈팅

> **실제 운영 사례**: 카카오클라우드(Kakao Cloud) NPU 인스턴스 구독 및 무료체험 후 리소스 정리  
> **핵심 문제**: 콘솔에서 인스턴스 및 키를 모두 삭제했음에도 불구하고 300만 원 이상 폭탄 과금 발생  
> **최종 해결책**: 사용자의 개별 리소스 수동 삭제가 아닌, **고객센터에 '계정 및 전 자원 완전 삭제(Account Termination)' 공식 요청**을 통한 백엔드 강제 정리

<a id="real-case"></a>
## 🚨 [핵심 실무 사례] 카카오클라우드 NPU 구독 후 인스턴스 전면 삭제에도 300만 원 이상 폭탄 과금 발생 및 고객센터 계정 삭제 요청을 통한 해결

### 📋 6단계 엔지니어링 표준 분석표

| 단계 | 항목 | 상세 내용 |
|:---:|:---:|---|
| **1단계** | **증상<br>(Symptom)** | • 카카오클라우드 NPU(Neural Processing Unit) 가속기 서비스를 구독하여 무료 사용 기간 동안 연구/실습을 진행함.<br>• 무료 프로모션 기간 종료에 맞춰 콘솔에 접속하여 **모든 NPU 인스턴스와 발급된 접속 키(키페어)를 전면 삭제** 완료함.<br>• 그러나 익월 청구서 확인 시, 모든 인스턴스를 삭제했음에도 불구하고 **300만 원 이상의 대규모 폭탄 과금**이 신용카드로 청구되거나 청구서로 발행됨. |
| **2단계** | **가설<br>(Hypothesis)** | • 사용자가 UI 화면에서 '인스턴스'와 '키'만 삭제했을 뿐, 카카오클라우드 내부에서 NPU 할당 단위로 묶여 있는 **백엔드 예약 풀(Reservation Pool), 가속기 슬롯, 전용 볼륨 및 보이지 않는 하위 의존 설정**들이 해제되지 않고 백그라운드에서 시간당 비용으로 계속 과금되고 있을 것이다.<br>• 카카오클라우드 콘솔 특성상 AWS의 CloudWatch/Billing 대시보드처럼 **"현재 어떤 리소스가 과금을 유발하는지 한눈에 보여주는 통합 대시보드가 부재"**하여 사용자가 잔여 자원을 인지하지 못했을 것이다. |
| **3단계** | **검증<br>(Verification)** | • 사용자가 콘솔 메뉴를 샅샅이 뒤졌으나 인스턴스 목록은 이미 비어있어 더 이상 수동으로 삭제할 대상을 UI에서 찾을 수 없음.<br>• 고객센터에 청구 내역 소명 및 잔여 자원 조회를 긴급 문의함.<br>• 확인 결과: 인스턴스는 꺼졌으나, **콘솔 UI 상에 직관적으로 드러나지 않는 NPU 전용 백엔드 파티션 및 하위 종속 설정들이 여전히 활성화(Active) 상태**로 남아있어 익월까지 과금이 누적되고 있었음이 검증됨. |
| **4단계** | **조치<br>(Action)** | • **핵심 전환**: 사용자가 콘솔에서 이것저것 찾아 지우려 애쓰는 것은 불가능하다고 판단, **고객센터에 공식 긴급 티켓을 접수하여 "계정 탈퇴 및 계정에 귀속된 모든 NPU 구독/하위 설정 전면 강제 삭제(Total Account Decommissioning)"를 요청함**.<br>• ⚠️ **실무 충격 요인**: 카카오클라우드 기술지원팀 및 운영진 자체도 통합 대시보드가 없고 백엔드에 숨겨진 설정들이 복잡하게 얽혀 있어, **고객센터 엔지니어들이 모든 설정을 수동 추적하여 완전히 삭제하는 데만 수 주가 소요**되었으며, 결국 다음 달이 되어서야 모든 잔여 자원 정리가 완료됨. |
| **5단계** | **결과<br>(Result)** | • 고객센터 최고위 엔지니어링 레벨에서 백엔드 잔여 설정을 강제 회수하고 계정을 영구 폐쇄함으로써 비정상 과금 파이프라인을 원천 차단함.<br>• 사용자의 정상적인 인스턴스 삭제 시도 증빙 및 콘솔 대시보드 가시성 결여 문제를 소명하여 **300만 원 이상의 부당 과금에 대한 청구 취소 및 감면 조치**를 이끌어냄. |
| **6단계** | **재발 방지<br>(Prevention)** | 1. **신용카드 사전 등록 주의**: 클라우드 NPU/GPU 고가 리소스 구독 전, 한도가 무제한인 법인/개인 신용카드를 무분별하게 등록하지 말고, 한도 제한 체크카드나 가상 카드를 활용하거나 사용 직후 결제 수단을 철저히 관리함.<br>2. **대시보드 부재 클라우드 이용 원칙**: 통합 대시보드가 미비한 클라우드 서비스를 무료 프로모션으로 이용할 때는, **단순 인스턴스 삭제를 맹신하지 말고 무료 기간 종료 직전 고객센터에 '계정 탈퇴 및 전 자원 삭제 요청'을 공식 접수하여 잔여 자원 0건 확약을 받는 프로세스**를 정립함. |

---

### 💡 실무 엔지니어링 교훈 (Lessons Learned)
> **"보이지 않는 리소스가 가장 위험한 과금의 주범이다."**  
> 대부분의 클라우드 초심자는 콘솔의 '인스턴스(가상머신)' 목록만 비어있으면 과금이 멈출 것이라 믿습니다. 하지만 NPU, GPU, 전용 호스트, 백엔드 인터페이스 같은 고가 자원은 인스턴스를 지워도 하위 예약 풀이 살아남아 월 수백만 원의 비용을 청구합니다. 특히 통합 자원 모니터링 대시보드가 없는 환경에서는 **"고객센터를 통한 계정 전면 삭제 요청"**만이 유일하고 확실한 트러블슈팅 방법입니다.

## 📌 [보조 실무 사례] AWS 인프라 환경에서의 트러블슈팅 요약

| 사례 | 문제 증상 | 핵심 원인 | 조치 및 해결 |
|---|---|---|---|
| **AWS 사례 1** | SSH 접속 시 `Operation timed out` | 유동 ISP 공인 IP 변동으로 보안 그룹 `/32` 불일치 | 현재 공인 IP 확인 후 보안 그룹 인바운드 규칙 갱신 |
| **AWS 사례 2** | 보안 그룹 80 오픈 후 외부 웹 접속 불가 | 서브넷 라우팅 테이블에 `0.0.0.0/0 ➔ IGW` 미등록 | 라우팅 테이블에 인터넷 게이트웨이 기본 라우트 등록 |
| **AWS 사례 3** | 메인은 정상이나 `/health`에서 `404 Not Found` | Nginx `default` 가상 호스트가 80포트 독점 선점 | `sites-enabled/default` 비활성화 및 전용 location 블록 적용 |
| **AWS 사례 4** | IAM 최소권한 RunInstances 권한 부족 | 인스턴스 동반 EBS 볼륨 생성 및 서브넷 바인딩 API 누락 | 필수 연관 액션 선별 허용 및 무관한 S3/RDS 명시적 Deny |
