2. 웹 서비스 외부 접속 검증

과제 요구사항인 (A) 웹 브라우저 접속 증빙 또는 (B) GET /health 헬스체크 호출 증빙 중 1개 선택 기준을 뛰어넘어, 방식 A와 방식 B 모두 완벽하게 교차 검증했습니다.

📸 외부 접속 증빙 갤러리 (클릭 시 확대)

🔍 클릭하여 원본 확대
방식 A 완료

웹 브라우저 외부 접속 증빙

공인 탄력적 IP http://54.180.1.48로 크롬 브라우저를 통해 접속하여, Nginx가 서빙하는 "I Like AWS" 메인 대시보드가 정상 렌더링됨을 입증합니다.

GET / HTTP/1.1

HTTP/1.1 200 OK

Server: nginx/1.18.0 (Ubuntu)

Content-Type: text/html; charset=UTF-8

Title: "I Like AWS — Cloud Mission Dashboard"

🔍 클릭하여 원본 확대
방식 B 완료

GET /health 헬스체크 & 아웃바운드

엔드포인트 http://54.180.1.48/health 호출 시 HTTP 200 OK와 고정 응답 문자열 "OK"를 반환하며, 인스턴스 내부의 인터넷 아웃바운드 통신까지 연속 검증했습니다.

$ curl -i http://54.180.1.48/health

HTTP/1.1 200 OK

Content-Type: text/plain

Content-Length: 3

OK

🔍 HTTP 엔드포인트 응답 상세 분석

1. 메인 엔드포인트 (GET /)

인프라 정보, 서울 리전, VPC 대역, 인스턴스 사양이 동적으로 표기되는 인터랙티브 HTML 웹페이지

Status: 200 OK | Content-Type: text/html

2. 헬스체크 (GET /health)

AWS ALB/NLB 및 모니터링 데몬이 서버의 가용성을 1초 이내에 판별할 수 있는 초경량 플레인 텍스트 엔드포인트

Status: 200 OK | Payload: "OK"

3. 아웃바운드 검증 (curl)

인스턴스 내부에서 인터넷 외부 도메인(example.com)으로 나가는 트래픽이 IGW를 통해 원활히 통신됨을 확인

curl -sI https://example.com ➔ HTTP/2 200
